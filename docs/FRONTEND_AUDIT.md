Generated by `frontend/scripts/design-audit.mjs`, which measures the
`CLAUDE.md` accessibility floor against the **running** app — real painted
pixels, real layout boxes. Not a code review; every number below was measured.

```bash
cd frontend && npm run dev                     # terminal 1
node scripts/design-audit.mjs                  # terminal 2
```

Coverage: 9 routes × 4 theme states (Day / Night / Night-vision / Sunlight)
× 3 text scales (100 / 125 / 150 %) = 108 screen states.

### Pillar surfaces added since (transport, tourism)

scale. **Zero** contrast, heading, touch, typography or overflow failures inside
`pillars/transport/*` and `pillars/tourism/*`. Both are Canvas 2D, no tile
server, no CDN, no new dependency — a tile map would be dead in airplane mode,

## Open — BACKEND, Lane B (Dhanesh): a model response is reaching the page

`GET /api/pillars/tourism/brief` returns the **router's chat-intent envelope**
in `interpretation` instead of a written brief:

```
```json
{"intent": "other", "reply": "I am the Lamer Konekte assistant. I can h…"}
```
```

Measured live on **2 of 8 sites** — Trou aux Biches and Belle Mare. Rendered
as-is, that puts a chatbot refusal on screen labelled as a tourism
interpretation: an honesty failure, and the most visible thing on the page in a
demo.

- **Where:** `backend/app/pillars/tourism/module.py` → `_interpret()`, which
  hands the chat-intent response through instead of the brief prompt's output.
  The module's own docstring already says *"a missing sentence is honest; a
  fabricated one is not"* — a chat refusal presented as analysis is the
  fabricated case.
- **Frontend, already shipped:** `TourismSurface` refuses to present a
  malformed payload as content and falls into its existing "no interpretation"
  state. That is a guard, **not the fix** — the backend still emits it, and any
  other consumer of the endpoint still gets it.

## Deliberately NOT fixed — needs a team decision

**White-on-coral on legacy `.primary` buttons: 2.67:1** across Day, Night and
Night-vision, on `/record`, `/log`, `/declaration`.

This is the *documented* tradeoff already recorded in `CLAUDE.md`:

> `--action-contrast: #2A0C06` … white-on-coral measures 2.81:1 and fails …
> *(styles.css still paints legacy buttons white-on-coral — pre-existing, left
> untouched by the render-identically rule.)*

New components already use dark-on-coral and pass. Fixing the legacy sheet
means changing the most prominent button on every shipped page — a redesign
decision, not a drive-by. **This is the single highest-impact contrast fix
available.**

Similarly left alone: `p.banner` (the permanent AI-limitation disclaimer) at
14 px app-wide, and `p.bento-sub` at **13 px** — off the 12/14/16 scale
entirely. Both are type-scale changes that would shift layout on teammates'
in-flight pages.

## Systemic: the 48 px vs 56 px touch floor

`CLAUDE.md` mandates **56 × 56 px**. `styles.css` sets `button, a { min-height: 48px }`
app-wide, so essentially every legacy control is 48 px:

- `button.lk-header-btn` 48 × 48 (theme + a11y toggles)
- `button.lang-switch` 64 × 48
- side-nav links 220 × 48
- `.primary` / `.secondary` buttons ~48–50 px tall

`--touch-min: 56px` exists in `tokens.css` and new components honour it; the
legacy sheet predates it. Raising one line moves every button in the app, so
it belongs in the redesign — but it should be **first** on that list, because
it's one declaration and it's the floor the whole product is justified on
(gloves, wet hands, a moving boat).
