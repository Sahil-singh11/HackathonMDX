## Pillar latency — the number that shaped two designs

| Call | Time |
|---|---|
| `/api/pillars/tourism/brief` (8 sites, hosted Gemma) | **>120 s (timeout)** |
| `/api/pillars/energy/resource` (5 sites, hosted Gemma) | **>120 s (timeout)** |
| `/api/pillars/tourism/brief` (8 sites, mock provider) | **0.039 s** |
| `/api/pillars/tourism/provenance` (probe, fetch only) | **0.030 s** |
| `/api/pillars/energy/provenance` (probe, fetch only) | **0.008 s** |

Hosted Gemma is ~20–30 s per call, and one call per site does not scale. Two
consequences, both shipped:

1. Interpretation is **capped at the top 3 ranked sites** in both pillars. Every
   site still returns full deterministic figures; the rest have an empty
   `interpretation`, which the schema and UI already handle.
2. The `/pillars` index uses a **provenance probe** (`fetch()` only, no
   inference) instead of full results — a 4000× difference.

## Determinism verification

Energy pillar figures were checked against an independent hand calculation for
all five candidate sites on live data — **all five matched**.

| Site | H (m) | T (s) | wind (km/h) | wave kW/m | wind W/m² |
|---|---|---|---|---|---|
| se_coast_offshore | 2.28 | 10.9 | 8.0 | 27.76 | 6.7 |
| south_coast_offshore | 2.22 | 11.25 | 12.3 | 27.17 | 24.4 |
| east_coast_offshore | 1.68 | 8.8 | 13.5 | 12.17 | 32.3 |
| north_channel | 1.06 | 8.5 | 25.2 | 4.68 | 210.1 |
| west_coast_offshore | 1.72 | 12.1 | 11.9 | 17.54 | 22.1 |

Formulas: `0.49·H²·T` kW/m and `0.5·1.225·(kmh/3.6)³` W/m². Physics agrees with
site exposure — the windward south-east tops wave power; the north channel is
lowest on wave and highest on wind from funnelling.

## Known gaps — not measured, do not claim

- **No token has ever been generated by the browser model.** Task 2b's "hello"
  gate was never cleared: it needs a WebGPU browser and a 2.01 GB download. The
  download, OPFS cache, capability detection, decline and cancel paths are real
  and tested; `Engine.create` → first token is not.
- **The web model artifact is 2.01 GB**, not the ~1.3 GB in brief §5. That figure
  describes the Q4 on-disk weights, not the `.litertlm` web build.
- **Task 2d (per-language quality table) was never run** — it needs the working
  model. There is no measurement of model-generated Kreol or French quality.
  `docs/MORISYEN_LANGUAGE_REPORT.md` predates this phase and is not 2d's output.
- **Languages shipped: English and Kreol Morisien only.** There is no French
  dictionary; French appears only as retrieval keywords in the grounding matcher.
- **All Morisyen strings are unreviewed** — rows 10–16 of
  `docs/MORISYEN_HUMAN_REVIEW.md`, all `_pending_`.
- **No screenshots.** This environment has no browser. Routes to capture:
  `/assistant`, `/pillars`, `/pillars/tourism`, `/pillars/energy` with
  `PILLARS_ENABLED=fisheries,tourism,energy`.
- **Wave figures are indicative, not accurate.** Open-Meteo's `wave_period` is
  not identified as an energy period; the formula requires one, giving ~10–20%
  uncertainty in an undetermined direction. All candidate sites are nearshore,
  where the deep-water formula overstates.
- **Suitability and resource thresholds are my own judgement** from ordinary
  recreational guidance, labelled as not a safety standard. Unreviewed by anyone
  with domain expertise.
